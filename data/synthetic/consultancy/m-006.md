# Data Migration Checklist

## Purpose

This checklist gives implementation teams a generic sequence for moving data into an ETRM or CTRM platform. It is a playbook for general use and holds no client-specific facts. Teams should adapt each step to the scope and constraints of their own engagement.

**Effective date:** 2025-10-01
**Document type:** Checklist

## Before You Start

- Confirm the scope of the migration with the engagement lead and record the agreed source systems.
- Profile the source data to identify duplicates, missing reference values, and inconsistent formats.
- Agree on owners for each data domain so that questions can be routed quickly during cutover.
- Set up a staging environment that mirrors the target configuration as closely as practical.

## Load Sequence

Load static data before any transactional data. Follow this order:

1. **Counterparties.** Load legal entities, identifiers, and credit attributes first, since most other records refer to them.
2. **Books.** Load the book and portfolio hierarchy, including ownership and reporting attributes.
3. **Products.** Load instrument and product definitions, including conventions and reference data they depend on.
4. **Trades.** Load transactional records only after the static data above has been validated.

Do not start a later stage until the previous stage has passed its checks.

## Reconciliation

After each load, reconcile the results against the source:

- Compare trade counts by status and by book between source and target.
- Compare total notional by currency and by book between source and target.
- Record any variance, investigate its cause, and document the resolution before proceeding.

Reconciliation should be repeated after each load, not only at the end of the migration.

## Script Management

- Keep all migration scripts under version control, including mapping files and transformation logic.
- Tag the script version used for each production load so that results can be reproduced.
- Review script changes before they are merged and record the reason for each change.
- Store configuration values separately from code, and never hard-code environment-specific settings.

## Cutover Checks

- Freeze source changes for the agreed window.
- Run the full load sequence in the production-like rehearsal and confirm that reconciliation passes.
- Obtain sign-off from the data owners for each domain before go-live.
- Keep a rollback plan and confirm that the source system remains available until sign-off is complete.

## Post-Migration

- Monitor exceptions and reconciliation breaks for the first business cycle after go-live.
- Archive the final reconciliation reports and script versions with the project records.
